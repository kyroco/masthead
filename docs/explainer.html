Masthead, a plugin for Claude Code

Rules that hold, even when the session is long

Masthead turns a team's working rules into small checks the AI cannot talk its way past. This page explains what you get, how a session looks with it on, and why each piece is built the way it is. No programming knowledge needed.

The idea in one picture

Write "never push without running the tests" into the file Claude reads at the start, and it works for a while. Long sessions forget, and a forgotten rule fails quietly. Masthead puts the rule in front of the action instead, every time.

How a session looks

You type one command with an issue number. Claude does the rest and asks you only when something is genuinely yours to decide.

The review, up close

When the change is finished, Claude does not grade its own work. It sends the diff, and nothing else, to reviewers who each take one angle. They cannot edit, cannot reach the network, and never see the author's explanation. A separate judge throws out what it cannot prove and hands back a fix list with a file and line for each item.

Each decision, and why

  1. A rule is a gate, not a sentence

    The rules that matter are small programs that run just before Claude acts and refuse when the rule is broken. You notice nothing until one refuses, and then you see a short reason.

    We wrote the rules in prose first. They held for about three hours. A gate cannot forget, and it never passes silently.

  2. Secrets are never read

    Claude cannot open environment files, keys, tokens, password files or cloud credentials. If it needs a value, it asks you.

    A secret that enters the conversation is in the transcript and in whatever Claude writes next. Refusing the read is the only place to stop that.

  3. Nothing irreversible

    Force pushes, history rewrites, deleting unmerged branches and destructive data commands are refused.

    Everything else can be reviewed and reverted. These cannot. A refusal costs a sentence; the alternative costs a weekend.

  4. Tests pass before anything is pushed

    If you say yes at setup, a push is refused until the test command has passed on the exact commit being pushed. Claude runs the tests itself; the gate only checks the receipt.

    "I ran the tests" is a claim. A receipt that names the commit is a fact.

  5. Reviewers are blind, and a judge keeps only what is proven

    Several reviewers, one angle each, plus a security reviewer when the change touches secrets or untrusted input. None can edit or reach the network. The judge hands back a fix list.

    A reviewer who can edit stops reviewing and starts fixing. A reviewer who can reach the network can be talked to. The judge exists because reviewers disagree and the author should not be the one deciding.

  6. One issue per session

    One issue, one worktree, one branch, one pull request. A foreman mode runs several workers in parallel, one fresh session each.

    A session that carries several pieces of work drifts. Many short sessions are cheap; one long one is not.

  7. Honest handoffs

    A brief to a helper must say what the author claims, what is not proved, and how a fix will be proved.

    A helper starts with only its brief. Whatever is left out, it never learns.

  8. A memory across sessions, if you want one

    With Korium connected, each session searches what earlier sessions learned before its first change and saves what it learned at the end.

    Korium is a product from Kyroco, the company behind Masthead. It has a free plan, but it is an account and a sign-in, and that is your decision, not ours.

  9. Your repository states its facts

    A small settings file tells Masthead your test command and where it may keep working files. A repository that states nothing still gets every guard rail; the ones that need a fact stand aside.

    Facts belong to the repository, so a teammate who clones it gets the same rails with nothing to configure.

  10. Opinions are switches; safety is not

    Korium, clean git history and the model gate for helpers are options you set at install. The secrets, irreversible-action and web-traffic rails are not.

    We hold opinions, and we made them switches. We also hold a few rules we would not want to be talked out of.

Installing it

Two commands in a terminal, then one inside Claude Code that asks three questions. Nothing is written until you say yes.

claude plugin marketplace add kyroco/masthead
claude plugin install masthead@masthead
/masthead:setup

Setup asks: just you or the team; tests before a push, with the test command it found; and whether to connect a memory now, later, or not at all. Run it again any time to change an answer.

Plain questions

Do I need a Korium account?
No. Everything except the memory works without one.
Does Masthead send anything anywhere?
No. There is no telemetry. The only network use is the memory, and only if you connect it.
Can it change my code on its own?
No. Gates refuse actions; they never take them.
What if a gate gets in my way?
Every refusal says what to do instead. The install options are switches, and the safety rails each have an off switch in the documentation for a real reason.
How do I remove it?
One command: claude plugin uninstall masthead@masthead. The small settings file it wrote is yours to delete.
